# Saheli agent layer — plan (2026-09-26)

Short plan for the four deliverables plus the browser-only food/grocery rule.
Order of shipping: **(2) progress→logs + (4) interrupts + allowlist + MCP removal**, then **(1) self-healing
step engine (Stagehand)**, then **(3) caregiver activity feed + daily snapshot**.

## Hard rules (code, not prompt)
- **Allowlist:** apollo, pharmeasy, instamart, swiggy, zepto, blinkit, zomato, uber. Everything else is refused
  with honest copy (`commerceAutomation/siteAllowlist.ts`), enforced at WA entry and at `runBrowserTask`.
- **Food/grocery = browser only.** Instamart/Swiggy/Zepto/Blinkit/Zomato never place via MCP:
  `shouldPreferBrowserForPartner` is hard-true, `shouldPreferMcpForPartner` hard-false, MCP adapter fallback removed,
  `placeMcpOrder` / `payCommerceOrder` / `submitOrderFlowCart` refuse these partners. MCP stays read-only (search) only.
- **Checkout guardrails** (unchanged + generalized): exactly the confirmed item(s)/qty, payable total == confirmed card,
  COD only (never UPI/card/wallet/pay-later/netbanking/QR), no membership/plan upsell, Place order at most once,
  stop on mismatch. Every agent (Stagehand) action is observed first and validated against a denylist before `act`.

## (2) Progress → activity log
- New Mongo `ActivityLog` (familyId, recipientUserId, actorUserId, kind, title, detail, data, severity, dayKey IST).
- `logActivity()` fire-and-forget. All browser `onProgress` lines, diagnostics and results are logged.
- WhatsApp to elder only: confirm card, OTP ask (stage `otp_ready` / need_otp result), final placed / honest failure,
  one short ack. Caregiver WhatsApp limited to safety alerts; everything else → activity log + in-app.

## (4) Interrupts
- `orderInterrupt.service.ts`: rules first, Gemini (Vertex flash) fallback → cancel | change | status | flow_reply | unrelated.
- Unrelated → handler returns null so the companion answers while the job continues. Status answers from draft/log.
  Change → re-search/re-confirm (or "already placing — reply cancel" if Place is in flight). OTP digits still route
  to the order; never retry OTP unprompted.

## (1) Self-healing step engine
- `@browserbasehq/stagehand@3.7.3` (CJS, LOCAL env) attached over CDP to our own Playwright Chromium.
- Model: `vertex/<VERTEX_BROWSER_MODEL | gemini-3.5-flash>` via ADC (no OpenAI/Anthropic).
- Per-site config (`agentLayer/siteConfigs.ts`) of step goals; deterministic path first, Stagehand `observe` →
  guardrail validate → `act(action)` fallback per step, with `cacheDir` action cache. Disabled cleanly if init fails.
- Dry-run mode stops at the payment page. Daily dry-run health check needs login for every allowlisted site, so it is
  documented and skipped (guest search health only).

## (3) Caregiver activity feed + daily snapshot
- APIs: `GET /api/care-records/:recipientUserId/activity`, `GET|POST /api/care-records/:recipientUserId/daily-snapshot`
  scoped to caregivers of that recipient's family.
- `DailySnapshot` per recipient/day generated by Gemini 3.5 Pro (scheduled + on demand).
- Dashboard page: timeline + snapshot.
